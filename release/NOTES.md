# Tapper · 已知限制（v1.4.6）

- 使用 Raw Input / DirectInput 独占输入的游戏会忽略模拟点击，需要驱动级方案（不在 v1 范围）。
- 独占全屏（exclusive fullscreen）游戏看不到悬浮层，建议改为「无边框窗口化」。
- 运行中光标会依次移动到各点击点，这是 SendInput 前台点击的固有行为。
- 「兼容（不抢鼠标）」方式会把点击消息直接投递给窗口；少数程序在主线程繁忙时会丢弃，必要时改用「双发」。
- 「双发」可能让同一次点击被算作两次，出现时请改回「标准」或「兼容」。
- 若目标程序以管理员身份运行，Tapper 也需要以管理员身份运行，否则模拟输入会被 UIPI 拦截。

## 点不动 / 热键没反应 的排查顺序

1. 面板点「测试一次点击」（2 秒后点一次），先切到目标窗口。
2. 没反应 → 安全防护里把「点击方式」切到 **兼容（不抢鼠标）**，再测。
3. 还没反应 → 确认目标程序是不是以管理员运行；是的话点「以管理员重启」。
4. 仍然不行 → 该程序很可能在输入层过滤了模拟输入（Raw Input / 注入标记），
   这属于程序自身的防护，普通用户态注入无法绕过；需要虚拟 HID 驱动级方案
   （如 Interception），代价是要装驱动、需要管理员，且可能被游戏判定为作弊，请自行评估。

热键：

- 日志里出现「键盘热键钩子已安装」即为生效。
- 钩子用「按键时间戳」判定，不依赖 KEYUP 一定能收到，全屏切换 / Alt+Tab 后再按仍能触发。
- 目标程序若以管理员运行，Tapper 也需要提权，否则收不到键盘输入。

## 关于高 CPS

- 支持到 200 CPS（5ms 间隔）。超过 50 CPS 会自动进入高频模式：按下时长压到 1–8ms，
  光标已在目标处时跳过移动。低频仍走兼容路径（18ms 按下 + 6ms 稳定期）。
- 引擎侧能达到的注入频率 ≠ 游戏实际收到的频率。60 帧渲染的程序每帧只处理一次输入，
  200 CPS 下每帧会挤进约 3 次点击，多余部分通常被合并或丢弃。
- 高频下「按下保持」会被自动限制，设很大的值没有意义。

## 停止行为（1.2.1 起）

- 启动后**不会**因为移动鼠标、切换窗口、鼠标点到别处而停止。
- 停止入口：F7、托盘菜单「紧急停止」、面板上的「紧急停止」按钮、「停止并退出」。
- 甩角急停默认关闭；开启后鼠标到屏幕左上角才会停（分屏时建议保持关闭）。
- 1.2.9 起补充一条：兼容 / 双发模式下，如果连点落点上的窗口没了（目标被移走或最小化），
  或者被**别的应用**盖住了，会**自动停止并提示**，需要你把遮挡窗口移开后手动重开——
  这是用户明确要求的策略（不做「隔着遮挡点后台窗口」）。标准模式仍只由快捷键 / 按钮停止。

## 顶部状态条位置

- 空闲时按住状态条拖动即可换位置，松开后自动保存；在状态条上点右键有菜单（打开主面板 / 状态条回到顶部）。
- 单击状态条 = 启动 / 停止（等同 F6 / F7），判定放在**抬起**那一刻。
- **拖着状态条改位置不会被当成「停止」**（1.4.1 改的）：按下时只记下「那一刻引擎在不在跑」，
  抬起时看这次有没有拖过 —— 拖过就只落新位置、引擎照跑；没拖过才按按下那一刻的状态启动或停止。
  以前是按下即停，于是「运行中想把状态条挪开一点」= 引擎被停掉，用户实测报过。
  越过拖动阈值 4 物理像素才算拖动手势，手抖不会把一次单击变成拖动。

## 悬浮层与鼠标的关系（1.2.5 起）

- 悬浮层窗口永远是「点击穿透」的：网页本身收不到任何鼠标事件，点击、拖动、右键菜单
  全部由全局鼠标钩子做命中测试后执行。好处是悬浮层永远不会挡住游戏，屏幕任意位置照常点击。
- 命中区按网页实测的渲染矩形计算（1.5 倍缩放下状态条约 496×48 物理像素；标记含下方文字标签，
  约 84×138 物理像素），**状态条画多大就只占多大，周围没有透明遮罩**。
- 指针移到状态条或标记上都会变成手型，运行 / 停止状态一致；移开后交还给窗口自己的光标。
  脚本模式下标记不能拖动，但空闲时仍能双击唤起面板，所以指针同样是手型。
- 运行时标记只是指示器：单击照旧落到游戏上，不抢鼠标。

## 打开主面板

- 三个入口，任选其一：
  1. **双击悬浮标记**（判定放在命中测试之前，手抖拖了一点也算；系统双击时间过短时按下限 500ms 兜底）；
  2. 在悬浮标记或顶部状态条上点右键 →「打开主面板」；
  3. 托盘图标右键 →「显示主面板」。
- 面板唤起后会短暂置顶约 1.5 秒，保证能盖在全屏游戏前面，随后自动取消置顶。
- 顶部状态条只负责启停 + 右键菜单：空闲时单击 = 启动（等同 F6），运行中或倒计时中单击 = 停止（等同 F7）；
  启停在**抬起**时判定，按住拖动只是改位置、不会停（见上节）；双击状态条没有任何动作。

## 状态条「回到顶部」为什么曾经点了没反应（1.2.8 修复）

- 拖动状态条时前端会先做本地预览（跟手），过去只在「预览值 == 服务端值」时才清掉预览；
  而 Rust 是 16ms 节流上报预览、抬起时才保存最终值，两者常差 1–2 像素，预览就永远盖住了真实配置
  —— 于是配置变了、画面却没动。
- 现在改成：只要服务端值发生任何变化（落定 / 复位 / 面板里改点位），本地预览立即作废，
  画面交回服务端值。判定逻辑抽成纯函数 `dropDragPreview`，有单测覆盖。

## 兼容模式怎么做到「不吃掉你的鼠标」（1.2.8 的做法，1.2.9 改坏，1.4.0 改回）

**先说结论**：你手里按着鼠标键的每一拍，兼容模式都不注入；抬起之后按下与抬起之间只留约 1 毫秒。
这两条合起来才保证「连点跑着，你照样点微信会话、拖窗口、缩放窗口」。

- 兼容模式不移动光标，只往**启动那一刻锁定在那个落点上的窗口**投递消息，
  所以落点永远是你标记的那个窗口，不会把点击送给刚好压在上面的陌生应用。
  投递前还会再核对一次落点窗口（判定和投递之间有几微秒缝隙）。
- **为什么「按住时让路」是必须的（1.2.9 的教训）**：注入的 `WM_LBUTTONDOWN` 后面必须跟一个
  `WM_LBUTTONUP`，这中间目标窗口认为左键**一直被按着**。你的真实按下如果正好掉进这段，
  窗口看到的就是「两次按下之间没有抬起」，于是把你的点击当成一次拖动的延续 ——
  表现就是「微信会话点不动、别的窗口也拖不动」。1.2.9 反过来让兼容模式「照点不误」，
  正是把这段干扰窗口开到了最大。
- **按下时长回到 1 毫秒**（1.2.9 强行拉到 12–60ms）：这是同一段干扰窗口的长度。
  实测用真实收件窗口量（临时探针，验证后已删除）：

  | 注入参数 | 窗口实际看到的 DOWN→UP | 4 次/秒时被按住的占比 |
  | --- | --- | --- |
  | 1.2.9（保持 12ms） | 中位 13.03ms（最小 12.08 / 最大 13.46） | 5.21% |
  | 1.4.0 = 1.2.8（保持 1ms） | 中位 1.24ms（最小 1.01 / 最大 1.77） | 0.50% |
  | 1.4.0 高频档（保持 2ms） | 中位 2.47ms（最小 2.19 / 最大 3.19） | 0.99% |

  也即抢占窗口缩小约 **10.5 倍**；再加上「你按着键时整拍不注入」，撞上的概率进一步归零。
- **抬起之后不再补同坐标移动**，消息集合回到 1.2.8 的 `MOVE → DOWN → UP`
  （探针实测序列即此，需要抢焦点时前面多一条 `ACTIVATE`）。
- 你手动按住按键期间不发 `WM_MOUSEACTIVATE`，目标窗口不会因此自己跳到前台抢焦点。
  现在这条只是兜底：那一拍本来整拍都不注入了。

**这条改动换回的是什么、又丢了什么，说清楚**：
1.2.9 拉长按下时长、抬起后补移动，是为了治「同窗口自绘 tab 页签有概率点不动」；
1.4.0 把这两条撤回，那类页签的命中率回到 1.2.8 的水平（个别自绘控件仍可能偶尔认不下）。
换回来的是你自己的点击和拖动不被吃掉 —— 按用户明确的取舍（「要确保能点击」）做的决定。

**诚实说明一条改不掉的限制**：PostMessage 无法伪造 `GetMessagePos` / `GetCursorPos` / 鼠标捕获，
所以个别自绘 tab、下拉控件在兼容模式下仍可能认不下这次点击（表现为「有概率点不动」）。
要 100% 命中只能用「标准（模拟鼠标）」，代价是连点期间光标被占用。

## 双屏：标记和状态条怎么挪到第二块屏幕（1.3.0 可拖过边缘，1.3.2 定下默认位置）

- **把标记或状态条直接拖过屏幕边缘，整块悬浮层（标记 + 状态条）就跟到那块屏**，落点自动落进那块屏里。
  主面板「屏幕」下拉仍然是另一个入口，两者走的是同一套切屏逻辑。
- 仍然**一块屏幕只有一个悬浮层**：标记和状态条永远在同一块屏上，不会出现「标记在副屏、状态条在主屏」。
- 拖进两块屏之间的**系统留白**（对角摆放、上下错开时中间那段空档）不算跨屏，会留在原来那块屏，
  免得悬浮层在空隙里乱跳。
- 换屏之后「没被拖着的那个」回默认位置（1.3.1 / 1.3.2 定下的三条）：
  · **拖状态条**过去 → 标记放到那块屏的**正中**；本来就在这块屏里的标记位置不动，只把贴边的夹进边距（离边 24 物理像素）。
  · **拖标记**过去 → 状态条回到那块屏的**顶部中间**（偏移复位为 `[0,0]`）。它的偏移是相对旧屏顶部中心存的，
    换一块屏留着也没意义，所以给个明确的默认位置，别让人去找一条看不见的状态条。
  · **面板「屏幕」下拉**换屏 → 标记按第一条规则处理，状态条按新屏换算后**放得下就保留、放不下才夹到整条可见**。
- 被拖着的那个不受复位影响：它的落点紧接着由这次拖动自己写，中途改写会让它在手里跳一下。
- 状态条的偏移本身是「相对所在屏顶部中心」存的，所以副屏（原点可以是负数、缩放也可能不同）
  和主屏各自摆位互不干扰。
- 屏幕选择按 `available_monitors()` 的**列表序号**，不再按显示器名字（`\\.\DISPLAY1` 这种会变、
  可能重复或为空，经常落回第一块，表现成「选副屏没反应」）；旧配置里残留的 `monitorName` 会被忽略。
- 切屏瞬间会向前端推一条 `overlay-geometry-changed`，让它立刻重取几何；否则前端要等 150ms 轮询，
  标记会按旧屏幕的换算短暂画出画面。
- 启动日志会把所有屏幕打印出来，排查时看这一行即可确认系统到底上报了几块屏、位置和缩放：
  `枚举到 2 块显示器：[0] \\.\DISPLAY1 (0,0) 2160x1440 x1.5 主屏；[1] \\.\DISPLAY2 (2160,-140) 1600x900 x1.0 副屏`
- 之前「标记明明拖不过去」的直接原因：配置里存的点位是 `x: 2136`，正好等于主屏右边界 2160 减去
  24 的边距——那是旧版本把标记**夹在屏幕边缘**留下的痕迹，拖动一过边缘就被夹回来，看起来像「拖不动」。
## 连点时打字丢焦点（1.4.2 修复）

- 现象：开着兼容（不抢鼠标）连点，切到微信聊天窗口打字，光标焦点反复丢失，打不了几个字就被顶走；
  有时又自己好了，「时好时坏」。
- 根因：`input::post_click` 每一次点击都会往目标窗口补一条 `WM_MOUSEACTIVATE`（消息号 0x0021），
  这条消息的意思就是「有鼠标按到我身上了，请你把自己激活到前台」。目标窗口收到就跳前台，
  顺带把输入焦点从你正在打字的窗口抢走。
- 为什么时好时坏：
  - 目标窗口本来就在前台时，这条激活是无害的 no-op —— 一切到别的窗口才发作；
  - 1.4.0 起「你手里按着鼠标键」那一拍会跳过激活，所以拖动窗口的间隙焦点能回来，像突然好了；
  - 前台切换本身受系统限制（前台锁），有时 Windows 直接拒绝后台进程抢前台，表现就是偶尔不丢。
- 现在的规则（`engine::want_activate`）：**只有前台本来就是目标窗口（或它的子窗口）时才发激活**；
  没锁定目标窗口时（测试一次点击、未开窗口保护的脚本步骤）保持旧行为照常发。
  目标在后台时只投 `WM_MOUSEMOVE` + `LBUTTONDOWN` / `LBUTTONUP`，点击照样进它的消息队列，
  但它不再跳到前台，你的输入焦点不会被打断。
- 代价：极少数自绘控件要靠「窗口处于激活态」才认下这一击。真遇到就把目标窗口点到前台再连点，
  或改用标准模式（代价是连点期间光标归它用）。
- 未能在本机验证的部分：需要真机复测「连点跑着 + 在微信聊天窗口连续打字」是否还会丢焦点；
  同时确认小程序那边仍在正常响应点击（关掉激活后收件是否受影响）。

## 悬浮层显示时也会抢焦点（1.4.3 修复）

- `ShowWindow` 的 `SW_SHOW` 按微软文档就是「**激活**并以当前尺寸位置显示」；
  `SW_SHOWNOACTIVATE` / `SW_SHOWNA` 才是「显示但不激活」。
- tao（Tauri 的窗口层）只在第一次显示时用 `SW_SHOWNOACTIVATE`（靠 `focused(false)` 打的那个标记），
  **之后的每次 `win.show()` 都走 `SW_SHOW`**。悬浮层是铺满整屏的透明窗口，被激活就等于抢到前台，
  你正在打字的窗口立刻失去输入焦点 —— 表现是「一开启悬浮按钮（F9 / 面板开关 / 换屏）就没法打字」。
- 现在 `overlay::show_without_activating` 直接调 `ShowWindow(SW_SHOWNOACTIVATE)`，
  显示悬浮层永远不动焦点；置顶用的 `SetWindowPos` 本来就带 `SWP_NOACTIVATE`，不受影响。
- 取证：1.4.3 起日志会写
  - 启动行带版本号与权限：`Tapper 启动 v1.4.3（管理员权限）`；
  - 开始点击时带上「方式」和「此刻前台」；
  - 运行中每 5 秒最多一行：`5 秒内前台窗口被切换 N 次，最后一次：A → B`。
    下次再报丢焦点，把这段日志发来就能直接看出是谁在抢（N 很大 = 每拍都在抢）。

## 悬浮标记长什么样（1.4.6）

- 空闲时是**冷蓝**的「鼠标箭头 + 五道放射」，运行中整枚切到**绿色**（和状态条「运行中」同语义）。配色只作用于悬浮标记本身，主面板仍是青色。
- 箭头整枚**在圆环里居中**，不做任何位移对齐（1.4.5 曾把箭头尖挪到落点上，用户反馈「偏移反而看着不正」，1.4.6 已去掉）。图标墨迹中心相对环心只偏约 1px / 0.5px，肉眼不可辨。
- 中心那个 **3px 小圆点才是真正被点击的像素**，现在落在箭头身子上（靠近箭尖与箭尾交界处）。点击坐标本身没变，别按图标看起来的位置去理解落点。
- 箭头形和 Windows 系统光标撞形是**已知取舍**：屏幕上会有两个箭头，认「环内那枚」。
- 换图标**不影响命中区**：拖动和右键菜单量的是 46×46 的标记框与下方标签的并集，图标在框内怎么挪都不改变可点范围。
